# Changelog

## 1.0.0-beta.2（2026-11-28）

- 完成前端 TypeScript 迁移；统计页默认保留轻量报告，并提供 React 交互图表入口。编辑器与评论选择表情后自动关闭面板，修复输入、资源加载失败重试和窄屏布局。
- 发布 Linux amd64、Linux arm64、Windows amd64 预编译包；一键入口直接下载部署包，Docker 使用预构建镜像，无需在安装服务器编译。后台通过官方签名清单下载核心包、校验、重启并保留回退能力，安装主机无需重新构建 Go 或前端资源。使用方法见 [预编译包使用说明](BINARY_RELEASES.md)。
- 保留已公开的 AI 流式生成清理顺序、PostgreSQL 插件回执 UTC 和 CI 修复；纳入验收时的导航取消修复。
- 新增团队写作模板独立表 `0072_writing_templates.sql`，保留既有表与迁移内容。核心更新保留已安装主题；随完整运行包提供 Chunnel 0.48.21，市场主题继续使用独立版本。

### Changed

- 客户端来源解析现在默认拒绝所有转发头；新增显式 `NEWPRESS_TRUSTED_PROXY_CIDRS`，仅在直接 TCP 对端可信时严格解析最多 32 跳的 XFF 链，并统一用于登录限速、会话元数据、评论来源摘要和回环只读边界。Compose 固定 proxy 地址，NGINX 覆盖 XFF，避免代理部署下访客身份合并或伪造。
- 管理认证的进程内状态现在有明确容量边界：最多 4096 个活动会话、每个身份 32 个会话和 4096 个登录失败来源键；request ID 只接受单个安全 ASCII 值，其他输入重新生成随机 ID。
- Runtime configuration now fails closed: invalid booleans, byte limits, durations, listen addresses, public origins, empty secret files, and idle/absolute session lifetime conflicts stop startup before runtime directories are created instead of silently falling back to defaults.

- Installed theme/plugin reads and public theme assets now reject symlink ancestors and linked manifest, template, schema, WASM, or asset files. ### Known limitations

- Persistent users, built-in RBAC, content-author ownership, single-instance device/session management, file-mode user/comment/navigation append-only audit, audit query/export, and local audit checkpoints are implemented, but MFA/recovery, invitations/password reset, custom-role editing, trusted-device binding, audit retention/archival, external signed/WORM anchoring, and cross-instance sessions/global revocation are not complete.
- Content authoring now includes protected server-rendered forms, Quick Draft, bounded revision comparison, identity-scoped autosave/recovery, short-lived draft preview, atomic status batch actions and an initial protected JSON API. Permanent content deletion, bulk author/category editing and a structured block editor are not implemented; draft preview uses the trusted active theme and is not the future isolated preview boundary for untrusted theme packages.
- Content and navigation JSON creation with an idempotency key commit their receipts with resources in file/PostgreSQL storage. Pre-upgrade lost completions and old writers during mixed-version deployment remain outside that guarantee. Login throttling and account sessions remain in memory; shared sessions/global revocation, API tokens/OAuth and cross-resource audit remain incomplete.
- The media library remains local-disk/single-node: reference-protected trash/recovery, retained-file verification and JSON metadata/lifecycle APIs are implemented. Image derivatives, EXIF stripping, malware scanning, private attachments, retention policies, object storage and PostgreSQL metadata integration remain incomplete.
- Dedicated taxonomy JSON CRUD, custom/plugin taxonomies, a cross-theme navigation-location declaration protocol, automatic navigation object-slug synchronization, WordPress menu conversion, and the extension Host API are not implemented. Schema-1 navigation export/import is available, but it is not a substitute for the source repository backup. Navigation object URLs are deliberate save-time snapshots and do not yet follow later slug changes automatically. Comment v1 now includes atomic batch moderation, safe editorial revisions, state-preserving revision recovery, server-derived staff replies, and durable file-mode summary audit; subscriptions/notifications, reputation/allowlists, shared cross-instance throttling, audit retention/archival, and external audit anchoring remain incomplete.
- The tools center can export settings/support data and atomically restore a validated navigation registry, but it does not run `pg_dump`, bundle media/deployment artifacts, upload backups, execute a full-site destructive restore, or import WordPress data yet.
- PostgreSQL 18.4 integration tests now pass locally. Windows race tests cannot initialize ThreadSanitizer with the available compiler/runtime; Linux CI remains the required race gate. Large-scale load, fault-injection and production recovery drills remain separate acceptance work.
- Docker configuration was not executed on the originating Windows environment because Docker CLI was unavailable; Linux CI validation remains required.
